## 1. Clean Architecture Blueprint

The project follows a strict layered architecture to ensure separation of concerns, scalability, and ease of testing.

```
[HTTP Request]
      │
      ▼
[Routes] ──────────────────► [validators/] (Zod Request Validation)
      │
      ▼
[Controllers] ─────────────► [utils/ApiResponse] & [utils/ApiError]
      │
      ▼
[Services] ────────────────► (Business & Domain Logic Transactions)
      │
      ▼
[Models] ──────────────────► (Mongoose Schemas & Hooks)
      │
      ▼
[MongoDB Atlas Database]
```

## 2. Server-Side Modules (`/server`)

### 2.1 Database Models
*   **[User.model.js](file:///e:/PATHFORGE/server/models/User.model.js)**:
    *   Defines attributes for `name`, unique lowercase indexed `email`, `password` (omitted from query results by default via `select: false`), default `role` (enum: `['user', 'admin']`), and dynamic `preferences`.
    *   Utilizes a pre-save hook to hash password strings automatically using `bcryptjs` (salt factors = 10) on document modification or creation.
    *   Exposes instance method `comparePassword(candidatePassword)` for secure credentials validation.
*   **[Settings.model.js](file:///e:/PATHFORGE/server/models/Settings.model.js)**:
    *   Keeps user configuration parameters (`theme`, `notificationsEnabled`, `language`, `timezone`) detached from the core user authentication document to optimize document lookups. Maps a one-to-one relationship back to the user object using Mongoose `ObjectId` referencing.

### 2.2 Input Validation
*   **[auth.validator.js](file:///e:/PATHFORGE/server/validators/auth.validator.js)**:
    *   Defines Zod request schema validation constraints (`name`, `email`, and strong `password` requirements).
    *   Exports validation interceptor `validateRegister` to safely validate `req.body` parameters, sanitize them, and throw standardized `ApiError` instances if payload errors are caught before reaching the controller.

### 2.3 Business Logic Services
*   **[auth.service.js](file:///e:/PATHFORGE/server/services/auth.service.js)**:
    *   Encapsulates user registration logic. It queries existing records to detect email duplicates, invokes user creation, sets up settings defaults under the same flow, and returns user structures stripped of security-sensitive parameters like passwords.

### 2.4 Controllers and Routing
*   **[auth.controller.js](file:///e:/PATHFORGE/server/controllers/auth.controller.js)**:
    *   Lightweight boundary controller. Parses validated payloads, passes them to services, and wraps responses within `ApiResponse` structures.
*   **[auth.routes.js](file:///e:/PATHFORGE/server/routes/auth.routes.js)**:
    *   Wires up `/register` endpoint mapping rules and mounts Zod middleware.
*   **[app.js](file:///e:/PATHFORGE/server/app.js)**:
    *   Integrates the auth router under the `/api/v1/auth` path prefix.

## 3. Client-Side Modules (`/client`)

### 3.1 Fetch Wrapper and Core Services
*   **[api.js](file:///e:/PATHFORGE/client/src/utils/api.js)**:
    *   Acts as the central request gateway wrapping native `fetch()`. Configured to support CORS session cookies (`credentials: "include"`), automatic JSON content headers, and standardized error parsing.
*   **[auth.service.js](file:///e:/PATHFORGE/client/src/services/auth.service.js)**:
    *   Exposes authentication-related client requests, notably `register(name, email, password)`.

### 3.2 Pages and Router
*   **[Register.jsx](file:///e:/PATHFORGE/client/src/pages/Register.jsx)**:
    *   Implements the register view utilizing `react-hook-form` + `@hookform/resolvers/zod` validation.
    *   Integrates submission tracking states, dynamic toast updates via `react-hot-toast`, and redirect handling via `react-router-dom` on successful registration.
*   **[AppRoutes.jsx](file:///e:/PATHFORGE/client/src/routes/AppRoutes.jsx)**:
    *   Declares client path routing properties for the newly created view under `/register`.

## 4. API Standardized Payload Specifications

### 4.1 Success Response Structure
Generated by **[ApiResponse.js](file:///e:/PATHFORGE/server/utils/ApiResponse.js)**:
```json
{
  "success": true,
  "statusCode": 201,
  "message": "User registered successfully",
  "data": {
    "user": {
      "_id": "60d0fe4f5311244304856f67",
      "name": "John Doe",
      "email": "john.doe@example.com",
      "role": "user",
      "preferences": {},
      "createdAt": "2026-07-21T10:15:20.000Z",
      "updatedAt": "2026-07-21T10:15:20.000Z"
    }
  }
}
```

### 4.2 Error Response Structure
Generated by **[ApiError.js](file:///e:/PATHFORGE/server/utils/ApiError.js)** and structured by **[error.middleware.js](file:///e:/PATHFORGE/server/middleware/error.middleware.js)**:
```json
{
  "success": false,
  "statusCode": 409,
  "message": "User with this email already exists",
  "errors": []
}
```

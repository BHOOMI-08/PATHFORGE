## 2. Server-Side Modules (`/server`)

### 2.1 Security Middleware
*   **[auth.middleware.js](file:///e:/PATHFORGE/server/middleware/auth.middleware.js)**:
    *   Acts as a gatekeeper for protected endpoints.
    *   Extracts `accessToken` cookies and verifies signatures via the token utility.
    *   Queries active User database profiles, strips out sensitive passwords or session keys, and attaches sanitized records to `req.user`.

### 2.2 JWT & Cookie Utilities
*   **[token.util.js](file:///e:/PATHFORGE/server/utils/token.util.js)**:
    *   Generates and validates short-lived Access Tokens (15 minutes) and long-lived Refresh Tokens (7 days).
*   **[cookie.util.js](file:///e:/PATHFORGE/server/utils/cookie.util.js)**:
    *   Assigns or clears HTTP-only, secure, `SameSite=Strict` cookies.

### 2.3 Services, Controllers, and Routing
*   **[auth.service.js](file:///e:/PATHFORGE/server/services/auth.service.js)**:
    *   `refreshAccessToken(incomingRefreshToken)`: Decodes and validates refresh token signatures. Verifies tokens match user records inside MongoDB to block token replay hijacking. Generates new token sets under Refresh Token Rotation (RTR).
    *   `getCurrentUser(userId)`: Returns user profile context data (excluding credentials).
*   **[auth.controller.js](file:///e:/PATHFORGE/server/controllers/auth.controller.js)**:
    *   `refresh`: Triggers token rotation service methods, appends new cookies to headers, and replies with structured responses.
    *   `getMe`: Returns `req.user` contexts established by security middlewares.
*   **[auth.routes.js](file:///e:/PATHFORGE/server/routes/auth.routes.js)**:
    *   Exposes `POST /refresh` and `GET /me` (protected via `authMiddleware`).

## 3. Client-Side Modules (`/client`)

### 3.1 Fetch Client Auto-Refresh Interceptor
*   **[api.js](file:///e:/PATHFORGE/client/src/utils/api.js)**:
    *   Wraps global `fetch()`. Integrates interceptors catching `401 Unauthorized` responses.
    *   Automatically runs silent backend token refreshment at `POST /auth/refresh`.
    *   On success, retries original requests; on failure, resets contexts and redirects to `/login`.
    *   Includes a single-retry constraint (`_retry` option flag) to prevent infinite redirect loops.

### 3.2 Global Auth Context Provider
*   **[AuthContext.jsx](file:///e:/PATHFORGE/client/src/context/AuthContext.jsx)**:
    *   Performs initial startup handshake. Triggers `/auth/me` on component mount to restore existing sessions.
    *   Exposes `user`, `isAuthenticated`, `isLoading`, `login()`, `logout()`, and `refreshUser()` via the custom `useAuth` hook.

### 3.3 Reusable Route Guards
*   **[AppRoutes.jsx](file:///e:/PATHFORGE/client/src/routes/AppRoutes.jsx)**:
    *   `ProtectedRoute`: Directs unauthenticated requests back to `/login` if no session is resolved.
    *   `PublicRoute`: Bounces logged-in users away from auth forms back to the dashboard.

### 3.4 Core Dashboard Layout & Navigation Config
*   **[DashboardLayout.jsx](file:///e:/PATHFORGE/client/src/layouts/DashboardLayout.jsx)**:
    *   Encapsulates the premium dark-themed layout shell.
    *   Features a responsive collapsible sidebar (toggleable width on desktop, overlay drawer on mobile), dynamic breadcrumbs, notification feeds, and profile avatar action dropdowns.
*   **[navigation.js](file:///e:/PATHFORGE/client/src/constants/navigation.js)**:
    *   Dynamic layout configuration schema mapping sidebar labels, icons (dynamically resolved from `lucide-react`), and target paths.

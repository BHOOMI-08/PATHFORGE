## 2. Server-Side Modules (`/server`)

### 2.1 Security & Session Utilities
*   **[token.util.js](file:///e:/PATHFORGE/server/utils/token.util.js)**:
    *   Exposes helpers to generate and verify JWTs: `generateAccessToken`, `generateRefreshToken`, `verifyAccessToken`, and `verifyRefreshToken`.
    *   Expirations are loaded from `.env`: Access Token = `15m`, Refresh Token = `7d`.
    *   Ensures JWT signing logic remains separated from data models.
*   **[cookie.util.js](file:///e:/PATHFORGE/server/utils/cookie.util.js)**:
    *   Encapsulates express cookie setting options: `setAccessCookie(res, token)` and `setRefreshCookie(res, token)`.
    *   Configured with secure headers: `httpOnly: true`, `secure: process.env.NODE_ENV === "production"`, `sameSite: "strict"`, and `path: "/"`.
    *   Exposes `clearAuthCookies(res)` to clear cookie sessions on user logout.

### 2.2 Database Models
*   **[User.model.js](file:///e:/PATHFORGE/server/models/User.model.js)**:
    *   Maintains the `comparePassword(candidatePassword)` instance method.
    *   Includes the `refreshToken` schema attribute to hold signed sessions in MongoDB.

### 2.3 Input Validation
*   **[auth.validator.js](file:///e:/PATHFORGE/server/validators/auth.validator.js)**:
    *   Defines Zod login verification schema checking `email` format and `password` presence.
    *   Exports `validateLogin` Express middleware intercepting bad payloads prior to controller execution.

### 2.4 Services, Controllers, and Routing
*   **[auth.service.js](file:///e:/PATHFORGE/server/services/auth.service.js)**:
    *   `loginUser({ email, password })`: Resolves matching records (including passwords), runs comparative checks, generates access and refresh JWTs, persists refresh tokens to User document in MongoDB, and returns sanitized data objects.
    *   `logoutUser(userId)`: Clears active `refreshToken` entries on the User record in the database.
*   **[auth.controller.js](file:///e:/PATHFORGE/server/controllers/auth.controller.js)**:
    *   `login`: Receives requests, calls login services, sets secure cookies via the cookie utility, and returns a standard `ApiResponse`.
    *   `logout`: Automatically retrieves active user signatures from headers/cookies, revokes database keys via service methods, and clears client cookies using `clearAuthCookies`.
*   **[auth.routes.js](file:///e:/PATHFORGE/server/routes/auth.routes.js)**:
    *   Exposes `POST /login` and `POST /logout`.

## 3. Client-Side Modules (`/client`)

### 3.1 Authentication Provider Context
*   **[AuthContext.jsx](file:///e:/PATHFORGE/client/src/context/AuthContext.jsx)**:
    *   Implements the global session state provider `<AuthProvider>`.
    *   Manages dynamic authentication state variables: `user`, `isAuthenticated`, `isLoading`.
    *   Exposes `login(email, password)` and `logout()` triggers calling respective service API queries.
    *   Exposes variables and actions globally using the custom `useAuth` hook.

### 3.2 Services, Pages, and Routes
*   **[auth.service.js](file:///e:/PATHFORGE/client/src/services/auth.service.js)**:
    *   Exposes `login(email, password)` and `logout()` using the global Fetch wrapper.
*   **[Login.jsx](file:///e:/PATHFORGE/client/src/pages/Login.jsx)**:
    *   Implements the sign-in visual panel with `react-hook-form` + `zod` client validation.
    *   Connects submission actions to `AuthContext.login()`, handles button spinner animations, handles form errors, and redirects authenticated sessions to the homepage placeholder `/`.
*   **[AppRoutes.jsx](file:///e:/PATHFORGE/client/src/routes/AppRoutes.jsx)**:
    *   Updates path routing configurations to map `/login` to the login component.
*   **[App.jsx](file:///e:/PATHFORGE/client/src/App.jsx)**:
    *   Wraps the central React routing structures with the `<AuthProvider>` context provider.
